# Taghvim — Agent Guidelines

## Product

Persian-language, RTL calendar web app inspired by `time.ir`, with a modern Iranian visual identity.

- Live at `https://taghv.im`. Repository: `https://github.com/farjadp/taghvim`.
- No accounts, authentication, advertising, or backend database.
- **Memorial panel.** The slot under the tools that used to hold prayer times shows one random person from the javidnaman list (`src/data/javidnaman.json`, ~3,200 identified names from javidnaman.iranintl.com). The pick happens on the server per request in `app/page.tsx`. Photos are hot-linked from the source CDN with `referrerPolicy="no-referrer"`; nothing is stored locally. Refresh the snapshot with `npm run sync:javidnaman` and commit the JSON. The line «اینجا پیش‌تر اوقات شرعی را اعلام می‌کردیم.» is deliberate — keep it.
- **Changelog.** `/changelog` renders `src/lib/changelog.ts`. Add a release entry in the same commit that ships the change, newest first, with the commit instant as an ISO string carrying an offset. `status: 'ready'` means committed but not deployed; flip it to `'live'` when it is pushed to taghv.im. Unit tests enforce the ordering, forbid a `ready` release below a `live` one, allow at most one `ready` (and only as the newest entry), and tie `package.json`'s version to the newest release. None of them can know whether a deploy happened — 0.9.0 reached taghv.im still marked `ready` and told every visitor it was unpublished — so run `npm run check:live` after each deploy; it fails while production still renders the badge.
  **Flip at push time, not at commit time.** Push means deploy here: Railway builds every push to `main`. So a release committed as `ready` and then pushed is `ready` on the live site until a later commit fixes it, and that window happened three times on 8 Sep. The rule: when Farjad approves a push, flip every `ready` release to `live` in its own commit and send both in the same push. `ready` is for work that is committed and **not** pushed; it must never reach production. The «در راه» list is explicitly not a promise — keep it that way.
- **Zodiac.** The side card names the sign of the current Persian month. This is a lookup, not astronomy: the Solar Hijri months map one to one onto the signs, which is why the Afghan calendar names its months حمل، ثور، جوزا. Glyphs are lucide's `Zodiac*` SVG icons via `components/zodiac-icon`; never the Unicode characters, which render as colour emoji on some systems. Keep `ZODIAC_SHORT_NOTICE` beside the sign and never add horoscope content.
- **Second clocks.** Tehran is and stays the main clock in the hero, and the second clocks now sit under it in the same card. The block may show the visitor's own time, added automatically only when their IANA zone differs from Tehran by offset, plus up to two cities they pick from `ZONES` in `src/lib/clocks.ts` (persisted as `taghvim-clocks`). A visitor on Tehran time with no cities chosen sees one quiet add link and nothing else. Never move the Tehran clock out of the hero or make a second clock the primary one. The hero must not clip its own overflow, because the city picker opens out of it; the sun drawing is clipped by its own wrapper instead, and the clock block sits at `z-20` so the footnote under it cannot swallow the picker's clicks.
- **Continuous holidays («تعطیلات پیوسته») and the countdown.** `src/lib/bridges.ts` finds every run of days off that is at least four days long, costs at most two days of leave, and hands over at least three days for free (`minFree` — four days bought with two days of leave is a swap, not a bridge; without that rule 1405 returns 54 rows instead of 10). A run may open or close on a leave day; the first version only merged holiday blocks and found 4 runs in 1405 where there are 10. Of two overlapping runs the one that costs at least as much and gives no more is dropped, so each holiday appears once per price. **Days off are read through `eventsForDate(date, groups)`**, never the raw tables, so a switched-off group can never produce a run the visitor cannot see — with the default groups nearly every run is Nowruz, and that is correct. Only Friday is the weekend; Thursday is not, and `BRIDGES_NOTICE` says so — keep it beside every list. A run resting on a computed lunar date is `uncertain` (`hasOfficialLunarDate` in events.ts tells the pinned dates apart) and the card says «ممکن است یک روز جابه‌جا شود». `src/lib/countdown.ts` is the same idea in days: whole days to the next holidays the visitor can see (never today, never a Friday, one entry per day) and to the fixed anchors, Nowruz and Yalda. **Whole days, never seconds** — the instant of the equinox is not in the data and `COUNTDOWN_NOTICE` says so; do not add a ticking countdown until that instant exists.
  **The naming is Farjad's, 9 Sep: «پل» is gone.** The feature is «تعطیلات پیوسته» and one of them is a «بازه», both words the app already used (`بازهٔ پشتیبانی‌شده`, `۹ روز پیوسته`). The code keeps `bridges` as its internal name and `/bridges` as the route — that slug stays because `/holidays` would promise the official holiday list, which this dataset explicitly is not, the same trap the `.ics` feed's name avoids.
  **Both live in the tools box, not on the page.** They are the first two tabs of `ToolsPanel`, and `DEFAULT_TOOL` is `bridges` — the box opens on it. They were a full-width row under the calendar for one commit (`adf3faa`); Farjad moved them into the tools on 9 Sep. `ToolsPanel` therefore takes `groups`; the other three tabs ignore it. The tool shows at most `BRIDGES_LIMIT` (3) runs over a rolling twelve months — the Persian year would leave it empty in Esfand — and links to `/bridges`, which lists the whole year and the next with the same switches read from `taghvim-view`, under `YearView` (`components/year-view.tsx`): the twelve months drawn from the same `bridges` array so the two cannot disagree, cell priority leave → run → holiday → Friday, because the leave day is the point of the picture. Measured: the year view is 868px tall at 1280 with 38px cells. **The trade-off to keep in mind:** the tools box sits far down the page, so this is much less discoverable than the row was — that was the explicit call, not an accident. `bridges-tool.tsx` and `countdown-tool.tsx` have no Next imports so the extension could use them; it does not yet.
- **Personal dates and the state's mark.** `src/lib/dates.ts` keeps the visitor's own birthdays and anniversaries in `taghvim-dates`, guarded the way `lib/view.ts` guards its record — a blob that is not an array is discarded whole, but one malformed entry inside a good array is skipped and the rest kept, because losing one name beats losing all of them. **This is the first thing the app stores that is content, not a setting**, and the content is people's names: `/about#privacy` says so in its own paragraph, and the Chrome Web Store listing links to that anchor, so that wording is a public claim — never quietly fold it back into «شش تنظیم». 30 Esfand is accepted (validated against a leap year) and clamped back to 29 Esfand in years that have no 30th, never spilling into Farvardin past Nowruz. The `.ics` export carries **no RRULE** — a yearly Gregorian rule drifts against the Solar Hijri year — so ten years are written out explicitly, and every event says the file does not update itself. It lives at `/dates`, a page rather than a sixth tool tab (the strip already scrolls sideways on a phone at five, and this is the only thing in the app the visitor writes); it is reached from the «روزشمار» tab, which answers the same question. `CalendarPanel`'s optional `marked` prop puts a dot on a day that carries one, and the legend grows a row **only when `marked` is passed** — a dot with no key is the mistake the holiday-colour report caught once.
  **The `state` category is Farjad's editorial call of 9 Sep and is enforced by a test.** No occasion in it carries «ایران»: `روز جمهوری اسلامی`, `بازگشت امام خمینی؛ آغاز دهه فجر`, and 22 Bahman is `متأسفانه شورش ۵۷ (جمهوری اسلامی)`. Every one of them renders behind `StateMark` — an **inline SVG, never the emoji**: 💩 is a colour bitmap that ignores the theme and the font, and this project draws its glyphs (the zodiac signs are SVG for the same reason). `components/occasions.tsx` is the single renderer for a list of occasions so the mark cannot be applied in one view and forgotten in another; use it rather than printing `event.title`. This is consistent with the memorial panel, which has always named the same government. **The same call renames the two men:** Khomeini is «دجال زمان (خمینی آفتابه به دست)» wherever he appears, and Khamenei would be «ضحاک تاریخ». Khamenei has **no occasion in this dataset and one must not be invented** to carry the name; the rule lives in a unit test that walks every day of the year, so adding a row later cannot quietly reintroduce either name in its official form. Farjad's spellings were normalised to the file's typography («متأسفانه», «آفتابه»), which he was told. The category stays **off by default**, and the `.ics` feed is `iran`-only, so none of this reaches a subscriber's calendar.
- **Display settings.** A gear in both headers opens theme (auto/light/dark), font size (14/16/18px root) and font family (Vazirmatn, Shabnam, Sahel, IRANSansX, IRANYekanX — all self-hosted, none fetched from a third party). **They are not all OFL:** Vazirmatn, Shabnam and Sahel are; IRANSansX and IRANYekanX are commercial faces from fontiran.com that Farjad holds a licence for, committed under `src/app/fonts/` with their provenance in the README there. Never call the set OFL. The two commercial faces are variable (weight axis 100-1000), so one `woff2` covers every weight instead of five imports, and their packages' "FaNum" builds must never be used: those map Latin digits onto Persian glyphs and would break the Gregorian date and the LTR clock, which the app renders with real Latin digits. Stored as `taghvim-theme`, `taghvim-size`, `taghvim-font`; applied as `data-theme` / `data-size` / `data-font` on `<html>` by an inline boot script in `app/layout.tsx` before first paint. Every colour must be a token from `globals.css` — never `bg-white`, never a hex literal in a component — because each token has a dark counterpart and axe runs in both themes. Text sizes are rem, never px, so the size setting scales them.
- **Secular by default.** (Shown on the site as «پیش‌فرض ایران عزیز»; that is the label Farjad chose, do not rename it back.) `EventGroups` replaces the removed `EventScope`: religious and state default off, world defaults on, and national/cultural (`iran`) events always remain. The calendar legend is now a two-row control: its original key plus «نمایش:», a non-interactive «ملی و فرهنگی» pill, and independent «مذهبی»، «دولتی»، «جهانی»، «یادبود» switches. No header scope switch remains. Religious visibility also gates the prayer navigation link and panel. Memorial visibility is independent and defaults on; preserve its content verbatim. Never move an event between `iran` and `state` without a reason in the commit message.
- **Install, crawlers and icons.** `app/manifest.ts` makes the site addable to a phone's home screen with its own icon and no browser chrome. **There is no service worker, so it is not offline-capable — never describe it as offline until one exists.** `app/sitemap.ts` and `app/robots.ts` both read `src/lib/routes.ts`, which is the single list of public routes; a unit test walks `src/app` and fails when a `page.tsx` ships without being added there, and another checks `SITE_ORIGIN` against `metadataBase`. The PNG icons (`public/icon-192.png`, `public/icon-512.png`, `src/app/apple-icon.png`) are rendered from `src/app/icon.svg` by `npm run build:icons` and committed — iOS ignores the manifest and reads `apple-icon.png`. The manifest's `background_color` must stay equal to `--color-paper`; a test enforces it.
- **Why this calendar.** The launch thread asked eight times what makes this different from `time.ir`. The answer lives in `/about#why`, and the footer links to it on every page. Keep that link, and keep the answer on the page it points at rather than duplicating it.
- **Mobile order.** On phones `<main>` is a flex column and the calendar row carries `order-first`, so the month grid opens the page and the hero, the second calendars card, the tools, the memorial and the prayer panel follow it. Measured before the change: the first day cell sat at 1128px on the 664px screen Playwright's iPhone 13 uses. Use `order-first`, not a number — the tools, memorial and prayer panels take no className and keep the default order 0, so any positive value on the grid would push them above everything. At `lg` the container returns to `block`, order stops applying and the original margins take over, so the desktop layout is untouched; a browser test asserts both orders. The full month still does not always clear the fold — 670px against 664 at the default font size, more at «بزرگ» or in a six-row month — so do not describe it as guaranteed.
- **Subscription feed.** `/calendar.ics` serves an iCalendar feed built by `src/lib/ics.ts`, for people who add it once to Google or Apple Calendar. **The URL must never change** — every subscriber is bound to it, and a rename empties their calendar silently rather than erroring. It carries `category: 'iran'` only: state and religious occasions are excluded by product decision, and the religious ones are also the dates this project cannot promise, so the feed is named «مناسبت‌های ملی و فرهنگی ایران» and never «تعطیلات رسمی». Window is the current Persian year −1 to +3, rebuilt daily. UIDs are `year-month-day-slot@taghv.im` and must stay stable: a changing UID makes clients add duplicates on every refresh instead of updating. RFC 5545 line rules are enforced by unit tests — CRLF everywhere, no line over **75 octets** (not characters; Persian is two bytes each), and folds never inside a UTF-8 sequence.
- **Help page and footer.** `/help` is the one place that explains how to do things; it names controls by the exact label the interface shows, so renaming a button means updating it. Its section list and its contents nav come from one array, and a browser test asserts they match and that every entry points at a section that exists. Do not duplicate the how-to elsewhere: `/about#subscribe` keeps only the lunar caveat and links to `/help#subscribe`. **The footer is deliberately short** — brand line, five pages, five shortcuts. The fifth shortcut, «گزارش اشکال یا پیشنهاد», is there against that rule by Farjad's explicit call on 9 Sep: a way to report that nobody can find is a report nobody files. Do not read it as licence to add a sixth. The maker, the company, the repository and the contact details live on `/about#links`; adding links back to the footer turns it into a sitemap. `/contact` still exists and is reached from `/about`, not from the footer or the header.
- **Social preview.** `public/og.png` is rendered by `npm run build:og` and committed. It uses **Chromium through Playwright, deliberately not `next/og`**: satori does not shape Arabic script, so «تقویم» comes out as disconnected letters. The image is declared in `app/layout.tsx` rather than left to the `app/opengraph-image.png` file convention, because that convention emits the image tags but not `og:image:alt` and ignored its `.alt.txt` sibling here. Keep the tokens in the script equal to `--color-paper`, `--color-forest` and `--color-clay`. One trap: `overflow` set on `<body>` propagates to the viewport and body computes to `visible`, so a bled decoration grew the document and pushed every block off the edge — the sunrise is clipped by its own wrapper instead.
- **Per-page metadata.** Every page builds its `Metadata` with `pageMetadata()` from `src/lib/seo.ts`, never by hand. Next inherits a parent's `openGraph` block wholesale, so a page that set only `title` kept the root's og:title — every secondary page shared the home page's name until 0.9.7. The helper sets `title`, `og:title`, `twitter:title`, the description in all three, the canonical and `og:url` from one argument, so they cannot diverge; a browser test asserts each route's canonical points at itself and no two pages share an og:title. Do not add a `title.template`: it would rewrite `title` and leave `og:title` behind. Structured data comes from the same module — `WebSite` and `WebApplication` in the layout, a two-level `BreadcrumbList` per secondary page. **No `SearchAction`**: the site has no search, and describing one to a crawler is a lie.
- **Browser extension (`extension/`).** An MV3 extension whose new tab is the calendar: today, the month grid, the day's occasions. Built by Vite (`extension/vite.config.ts`) from the **same source** — `src/lib/*` and the client panels are imported through the `@/` alias and must never be copied; only the shell `extension/src/new-tab.tsx` is the extension's own. Invariants, each enforced by `scripts/check-extension.mjs` after every build and by `src/lib/extension.test.ts`: **`permissions` and `host_permissions` are empty**, the default MV3 CSP is kept, the bundle contains no `fetch`/`XMLHttpRequest`/`WebSocket`/`eval`, no URL other than XML namespaces, React's error prefix and the one `taghv.im` link, and only `woff2` fonts ship (the build strips eot/ttf/woff and rewrites the `src` lists — 3.6 MB to 1.1 MB). MV3 forbids inline scripts, so the pre-paint theme script is emitted as `boot.js`; Vite's modulepreload polyfill is off because it is a `fetch`. The extension page has its own origin: the site's `localStorage` is not readable there, so settings start from defaults and the UI must not suggest otherwise. `TodayPanel` is exported in two halves (`TodayHero`, `OtherCalendars`) for this; `CalendarPanel` takes `showMemorialSwitch={false}` because no memorial is rendered. `tests/extension.spec.ts` serves the built files from a throwaway server with every other origin blocked and reads the Tehran date. `extension/dist` is git-ignored; `manifest.version` must equal `package.json`'s. `npm run package:extension` produces the upload ZIP (git-ignored, zipped from *inside* dist so `manifest.json` sits at the archive root, which the store requires) and renders `extension/store/newtab-{light,dark}.png` at 1280x800 from the built page — the listing shows the real thing, not a mockup. Icons come from `npm run build:icons`: 16/32/48/128 for Chrome and the store listing, 192/512 for the web manifest, and the small sizes use less padding because a 16% inset leaves an 11px glyph that reads as a smudge.
- **The Firefox build is the same package with a different manifest.** `TARGET=firefox` sends the same Vite config to `extension/dist-firefox`. `extension/manifest.json` is the base; `extension/manifest.firefox.json` is a **delta** — it adds `browser_specific_settings.gecko` (id `taghvim@taghv.im`, `strict_min_version` 140.0, `data_collection_permissions: {required: ['none']}`) and a `null` deletes `offline_enabled`. Never hand-maintain a second full manifest: two copies drift and nobody notices. `strict_min_version` is 140 because that is the floor for the data-collection key, and without it Firefox prompts for data consent on an add-on that collects nothing. No `gecko_android` block: `chrome_url_overrides.newtab` is desktop-only in Firefox (supported since 54), so the add-on is desktop-only by design and the resulting `KEY_FIREFOX_ANDROID_UNSUPPORTED_BY_MIN_VERSION` warning is expected. `scripts/check-extension.mjs` takes the dist folder as its argument and infers the target from the folder name. **AMO requires the source** of any bundled add-on, so `npm run package:extension` also emits `taghvim-<v>-source.zip` from `git archive HEAD` and runs Mozilla's `addons-linter`, failing the build on any error; two `UNSAFE_VAR_ASSIGNMENT` warnings remain and are React DOM's own minified `innerHTML` writes, unreachable from `src/`. `extension/FIREFOX.md` is the reviewer-facing build instructions and is deliberately **in English** — it is the one file in this repo that is. The `firefox` Playwright project runs `tests/extension.spec.ts` against `dist-firefox` in real Gecko: a green linter says nothing about whether the page paints, and Gecko is otherwise unexercised here.
- **Reporting a bug or a feature.** `src/lib/feedback.ts` builds a `mailto:` link and that is the whole channel — there is no form and must not be one. A form needs a third-party endpoint, which would break the `/about#privacy` promise that the memorial photo is the only external request and would break the extension's zero-request invariant outright; worse, Formspree-class endpoints are frequently unreachable from inside Iran, so the form would fail silently for exactly the people most likely to report something. Farjad chose mailto over a hosted form and over GitHub Issues on 9 Sep. `FeedbackPanel` is a client island only so it can add `location.pathname` and `navigator.userAgent` after mount; the server-rendered href is already valid and sendable, so nothing depends on JavaScript. Those two lines go in the body under a heading that says they can be deleted — never collect them silently, and never add anything the person cannot see before sending. The address is printed as text beside the buttons because `mailto:` does nothing on a machine with no mail client. The section lives at `/help#feedback` and `/contact#feedback`, the footer links to it, and the extension's header links to `https://taghv.im/help#feedback` rather than opening a compose window from a new tab. `scripts/check-extension.mjs` allows taghv.im **with a path** for that link and still nothing else.

- **Privacy claims.** `/about#privacy` is the privacy statement the Chrome Web Store listing links to, and the footer links to it from every page. **The site is not request-free:** the memorial photo is hot-linked from the source's CDN, so the visitor's browser reaches it and that service sees their IP; `referrerPolicy="no-referrer"` keeps the page URL out of it. The README claimed no third-party request at all until 0.9.10 — writing the statement is what caught it. Never round that down to zero again: say the memorial is the one exception and that turning its switch off removes it. The **extension** genuinely makes none, because it renders no memorial; that holds for both the Chrome and the Firefox package, which share a bundle. Fonts, icons and everything else are self-hosted.
- **Download page.** `/download` lists the ways to get the calendar onto a device, and its value is that it never claims something that is not built. The methods and their statuses are data in `src/lib/downloads.ts` — `ready`, `review`, `planned` — and the page renders whatever is there. **Do not hard-code a store link:** set `CHROME_STORE_URL` or `FIREFOX_STORE_URL` when that listing is approved and the card stops saying "in review" on its own. Add a status only for a state something is actually in; a `built` status existed for two hours on 9 Sep and was removed the moment the add-on was submitted, because a label nothing renders is untested surface. A method with no `action` renders no button; a dead "coming soon" link is worse than a sentence. A browser test asserts each status and that no web-store URL appears while the constant is null. Note the home page uses the app shell's own header, not `SiteHeader`, so the only path there from `/` is the footer.
- Approved design: warm light surfaces, deep green, restrained clay accents, locally hosted Vazirmatn typography; a matching dark palette; the memorial box is the one deliberately dark surface in light mode.
- Logo source: `src/app/icon.svg`, a sunrise/calendar-page mark. The header references `/icon.svg`, and Next.js uses the same asset as the browser icon. Do not duplicate its geometry.
- Stack: Next.js App Router, TypeScript, React 19 functional components, Tailwind CSS v4. No inline styling.

## Commands

```bash
npm install                              # restore dependencies (pinned in package-lock.json)
npm run dev -- --port 3100               # local development; port 3000 is occupied, do not stop it
npm test                                 # Vitest unit tests
npm run typecheck                        # TypeScript check
npm run build                            # production build
npm run test:e2e                         # Playwright desktop/mobile tests on port 3100
npm run sync:javidnaman                  # refresh src/data/javidnaman.json from the source site (manual, needs network)
npm run check:live                       # after every deploy: fails if production still shows «آمادهٔ انتشار»
npm run build:icons                      # regenerate the PNG app icons from src/app/icon.svg (commit the output)
npm run build:og                         # regenerate public/og.png, the social preview (commit the output)
npm run build:extension                  # build the Chrome extension into extension/dist and check the bundle
npm run build:extension:firefox          # same source, Gecko manifest, into extension/dist-firefox
npm run package:extension                # build both, zip for both stores (plus the AMO source zip), lint, and render the 1280x800 listing screenshots
npx playwright test --project=firefox    # the extension spec against the Firefox package, in real Gecko
npx playwright install chromium          # one-time Chromium install for E2E
```

Run unit tests, typecheck, build, and relevant browser tests before completing any change.

For an isolated worktree preview, use `npm run dev -- --port 3101` and `E2E_PORT=3101 npm run test:e2e`; the override prevents testing the main worktree's server on 3100.

## Date and data invariants

- Calendar instants are interpreted as civil dates in `Asia/Tehran`, never the host machine's timezone.
- Civil-date conversions return UTC noon. Supported range: Persian years 1200–1600 inclusive.
- Month grids start on Saturday and include adjacent-month padding. Out-of-range boundary padding is disabled in the UI and must not be passed to range-validated helpers.
- Lunar dates use `islamic-civil`, not Iranian observational dates. Preserve the visible computational-calendar notice.
- Events are a curated selection of recurring fixed Persian/Gregorian events plus lunar religious holidays computed via `islamic-civil`, not the full official calendar. Lunar holidays may differ from Iranian observational sightings by ±1 day. Preserve coverage warnings and never present this dataset as complete.
- `eventsForDate(date, groups = ALL_GROUPS)` is the single source of truth for both grid shading and the event list. A disabled group's rows disappear entirely, including holiday flags. `iran` always remains. The library default is inclusive; the UI passes its own preferences (religious/state off and world on by default).
- `OFFICIAL_LUNAR_OVERRIDES` pins lunar holidays to official Persian dates per year. It currently covers three dates in 1405 only.
- Prayer times use Adhan's Tehran method with city coordinates. Jafari midnight is the midpoint between sunset and the next day's fajr. Preserve approximation/method notices.
- The live clock uses the device clock in Tehran time, not NTP synchronization.
- `src/data/javidnaman.json` is a committed snapshot, not a database: the app never fetches the source at build or request time. The snapshot's `count` and `fetchedAt` are shown in the UI, so a stale snapshot is visible, not hidden.
- Persisted localStorage keys: `taghvim-city`, `taghvim-view`, `taghvim-theme`, `taghvim-size`, `taghvim-font`, `taghvim-clocks`. Every access is guarded for restricted-storage environments. `taghvim-view` is a strict four-boolean JSON object: `{"religious":false,"state":false,"world":true,"memorial":true}` by default. Corrupt, partial, extra-key or non-boolean data falls back to defaults. On first read without that key, migrate legacy `taghvim-scope`: `secular` maps to defaults; `all` enables religious/state too. Write the new record successfully before removing the old key. Storage exceptions never break rendering or in-memory switches.
- Calendar cells and tool tabs support RTL arrow-key navigation. Preserve keyboard behavior and midnight rollover regression tests.

## Code style

- Every code file (`.ts`, `.tsx`, `.mjs`, `.css`) starts with the header block below and carries inline comments on non-obvious logic. Bump `Version` in the header when the file's behaviour changes.

  ```ts
  // ============================================================================
  // Source: src/lib/events.ts
  // Version: 0.2.0 — 2026-09-07
  // Why: One or two lines on what this file is for.
  // Env / Deps: What it depends on or persists.
  // ============================================================================
  ```

- TypeScript over JavaScript.
- Functional React components only.
- Tailwind classes only — no inline styles. Colours only via the tokens in `globals.css` (`surface`, `paper`, `ink`, `muted`, `line`, `forest` for text, `forest-deep` for backgrounds, `leaf`, `clay`, `sand`, `holiday`, `memorial-*`).
- Keep the app Persian and RTL.
- Do not add account/auth/database functionality.
- Preserve all date and data disclaimers.
- Do not stop unrelated servers, especially the process on port 3000.
