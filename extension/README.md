# اکستنشن کروم و فایرفاکس — تب جدید، تقویم

تب جدید مرورگر را با تقویم جایگزین می‌کند: تاریخ امروز و ساعت تهران، ماه جاری، و مناسبت‌های روز. همان چیزی که `@shahram51` زیر تِرد لانچ خواست.

## ساخت و نصب

```bash
npm run build:extension          # کروم  → extension/dist
npm run build:extension:firefox  # فایرفاکس → extension/dist-firefox
```

هر دو خروجی در گیت نادیده گرفته می‌شوند. بعد در کروم:

1. `chrome://extensions` را باز کن و **Developer mode** را روشن کن.
2. **Load unpacked** را بزن و پوشهٔ `extension/dist` را انتخاب کن.
3. یک تب جدید باز کن.

هر بار که `build:extension` را دوباره اجرا کنی، در همان صفحه روی «بازخوانی» اکستنشن بزن.

در فایرفاکس:

1. `about:debugging#/runtime/this-firefox` را باز کن.
2. **Load Temporary Add-on** را بزن و `extension/dist-firefox/manifest.json` را انتخاب کن.
3. یک تب جدید باز کن.

یا با یک دستور، در یک پروفایل موقت و جدا از پروفایل خودت:

```bash
npx web-ext run --source-dir extension/dist-firefox
```

افزونهٔ موقت با بستن فایرفاکس پاک می‌شود. این محدودیت فایرفاکس است: افزونهٔ امضانشده فقط موقت نصب می‌شود.

## دو منیفست، یکی پایه و یکی دلتا

`manifest.json` منیفست کروم است و پایهٔ هر دو بیلد. `manifest.firefox.json` فقط تفاوت‌ها را دارد: بلوک `browser_specific_settings.gecko` — شناسه، حداقل نسخه، و اعلام اینکه هیچ داده‌ای جمع نمی‌شود — و یک `null` که `offline_enabled` را حذف می‌کند، چون کلید کروم‌اپ است و لینتر موزیلا به آن گیر می‌دهد. `vite.config.ts` این دو را ادغام می‌کند.

نسخهٔ دوم دستی نگه نمی‌داریم، چون دو منیفست دستی بعد از چند نسخه از هم دور می‌افتند و کسی متوجه نمی‌شود.

**حداقل فایرفاکس ۱۴۰.** پایین‌تر از آن کلید `data_collection_permissions` شناخته نمی‌شود و مرورگر بی‌دلیل از کاربر اجازهٔ داده می‌پرسد — برای افزونه‌ای که هیچ داده‌ای جمع نمی‌کند. روی فایرفاکس اندروید کار نمی‌کند، چون آنجا جایگزینی تب جدید پشتیبانی نمی‌شود.

**فایرفاکس موقع نصب می‌پرسد.** برخلاف کروم، فایرفاکس یک بار از کاربر می‌پرسد که اجازه می‌دهد تب جدید عوض شود. نمی‌شود دورش زد و نباید هم بشود؛ فقط در متن فروشگاه نوشته شده تا غافلگیر نشود.

## چه چیزی داخلش هست و چه چیزی نیست

| هست | نیست، عمداً |
| --- | --- |
| تاریخ امروز، روز هفته، ساعت زندهٔ تهران و ساعت شهرها | ابزارهای تاریخ (تبدیل، فاصله، سن) |
| ماه جاری با همان رنگ تعطیلی و اعداد میلادی · قمری | اوقات شرعی |
| مناسبت‌های روز و ماه | یادبود جاویدنامان |
| کلیدهای مذهبی، دولتی، جهانی | صفحهٔ تغییرات، راهنما، درباره |
| پوسته، اندازه و پنج قلم | هر چیزی که شبکه بخواهد |

تب جدید چیزی است که آدم به آن **نگاه** می‌کند، نه چیزی که در آن کار می‌کند. بقیه یک کلیک آن‌طرف‌تر روی [taghv.im](https://taghv.im) است.

## چیزهایی که باید بدانی

**هیچ مجوزی نمی‌خواهد.** `permissions` و `host_permissions` در منیفست خالی‌اند. هیچ درخواست شبکه‌ای وجود ندارد، هیچ آماری جمع نمی‌شود، هیچ کدی از بیرون بارگذاری نمی‌شود. `scripts/check-extension.mjs` بعد از هر بیلد همین‌ها را چک می‌کند و اگر یک `fetch` یا یک نشانی خارجی به بسته راه پیدا کند، بیلد را رد می‌کند.

**تنظیمات سایت به اکستنشن منتقل نمی‌شود.** صفحهٔ اکستنشن origin خودش را دارد (`chrome-extension://…`) و نمی‌تواند `localStorage` سایت taghv.im را بخواند. پس پوسته، قلم و کلیدهای مناسبت از همان پیش‌فرض‌های سایت شروع می‌شوند و جدا ذخیره می‌شوند. این محدودیت مرورگر است، نه یک باگ، و رابط هم چیزی جز این ادعا نمی‌کند.

**کد کپی نشده، ایمپورت شده.** پنل‌ها از `src/components` و منطق از `src/lib` می‌آیند — همان فایل‌هایی که سایت استفاده می‌کند. فقط پوستهٔ تب جدید (`extension/src/new-tab.tsx`) مال اکستنشن است. اگر تقویم سایت درست باشد، این هم درست است؛ اگر چیزی در سایت عوض شود، اینجا هم عوض می‌شود.

**اسکریپت پیش از رسم.** MV3 اسکریپت درون‌خطی را ممنوع می‌کند، پس همان اسکریپتی که سایت برای اعمال پوستهٔ تیره قبل از اولین رسم دارد، به‌عنوان `boot.js` جدا در بیلد تولید می‌شود. برای همین تب تیره فلاش سفید نمی‌زند.

**فقط woff2.** بسته‌های شبنم و ساحل فرمت‌های eot و ttf و woff هم دارند که کروم هرگز لازمشان ندارد. بیلد آن‌ها را حذف و فهرست `src` را بازنویسی می‌کند — ۳٫۶ مگابایت به ۱٫۱ مگابایت رسید.

## انتشار در فروشگاه‌ها

```bash
npm run package:extension
```

هر چیزی که دو فرم می‌خواهند را می‌سازد:

- `extension/taghvim-<version>.zip` — آپلود کروم.
- `extension/taghvim-<version>-firefox.zip` — آپلود فایرفاکس.
- `extension/taghvim-<version>-source.zip` — سورس، برای فایرفاکس. **این اختیاری نیست**: AMO برای هر افزونه‌ای که کدش باندل یا مینیفای شده باشد سورس را اجباری می‌خواهد و بدون آن ثبت را رد می‌کند. با `git archive HEAD` ساخته می‌شود، پس دقیقاً همان درختی است که کامیت شده — نه `node_modules`، نه `dist`، نه هیچ تغییر لوکالِ کامیت‌نشده. به همین دلیل اگر درخت کاری کامیت‌نشده داشته باشد، `package:extension` رد می‌شود: سورسی که به بازبین می‌دهی باید همانی باشد که بسته از آن ساخته شده.
- `extension/store/` — تصاویر لیستینگ:

همهٔ زیپ‌ها از **داخل** پوشهٔ بیلد بسته می‌شوند، چون هر دو فروشگاه بسته‌ای را که `manifest.json` در ریشه‌اش نباشد رد می‌کنند. هر سه در گیت نادیده گرفته می‌شوند.

قبل از اینکه چیزی ساخته شود، `addons-linter` خودِ موزیلا روی بستهٔ فایرفاکس اجرا می‌شود و هر خطا بیلد را رد می‌کند. دو هشدار `UNSAFE_VAR_ASSIGNMENT` می‌ماند که هر دو داخل رانتایم مینیفای‌شدهٔ ری‌اکت‌اند و از کد ما قابل رسیدن نیستند — در [`FIREFOX.md`](FIREFOX.md) توضیح داده شده، همان فایلی که برای بازبین AMO نوشته شده و به انگلیسی است.

| فایل | جای فرم |
| --- | --- |
| `store-icon-128.png` | Store icon، ۱۲۸×۱۲۸ |
| `newtab-light.png` · `newtab-dark.png` | Screenshots، ۱۲۸۰×۸۰۰ |
| `promo-small.png` | Small promo tile، ۴۴۰×۲۸۰ |
| `promo-marquee.png` | Marquee promo tile، ۱۴۰۰×۵۶۰ — فقط کروم |

اسکرین‌شات‌ها از صفحهٔ **ساخته‌شده** در مرورگر واقعی گرفته می‌شوند، نه ماکت. تایل‌ها کشیده می‌شوند، چون ۴۴۰×۲۸۰ برای نشان دادن یک گرید تقویم خیلی کوچک است.

**هر پنج تا ۲۴ بیتی و بدون کانال آلفا هستند** — فرم آلفا را رد می‌کند.

نسخهٔ `manifest.json` باید با `package.json` یکی باشد؛ یک تست واحد همین را چک می‌کند. فروشگاه اجازه نمی‌دهد یک شماره دو بار آپلود شود، پس برای هر آپلود تازه نسخه را بالا ببر.

## تست

- `npm test` — منیفست: MV3، بدون مجوز، آیکن‌ها موجود، نسخه برابر `package.json`؛ و دلتای فایرفاکس: شناسهٔ گِکو، حداقل نسخه، اعلام «هیچ داده‌ای»، و نبودن کلیدهای مخصوص کروم.
- `npm run build:extension` و `npm run build:extension:firefox` — بیلد به‌علاوهٔ بررسی بسته، هر کدام روی خروجی خودش.
- `npm run test:e2e` — صفحهٔ ساخته‌شده را با شبکهٔ مسدود بارگذاری می‌کند و تاریخ تهران را می‌خواند. اگر پوشهٔ بیلد نباشد، خودش می‌سازد.
- `npx playwright test --project=firefox` — همان تست‌ها، ولی در خودِ گِکو و روی بستهٔ فایرفاکس. سبز بودن لینتر موزیلا چیزی دربارهٔ درست رسم شدن صفحه نمی‌گوید؛ این می‌گوید. یک بار `npx playwright install firefox` لازم دارد.
